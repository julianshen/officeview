# Keep your canvas, borrow proven interactions

Build the sort/filter viewer on the canvas renderer you already own and borrow only interaction patterns, state models, and accessibility norms from Quadratic, Univer, FortuneSheet, and the best data grids, because none of the complete options embeds cleanly for viewing-only use. Quadratic demonstrates the performance ceiling with WebGL, spatial hashes, and worker isolation, yet it is closed-source since March 2026 ([Source](https://www.quadratichq.com/blog/comparing-the-5-best-open-source-spreadsheets)). Univer offers the cleanest filter and sort state model under Apache-2.0, yet its import, export, and collaboration are Pro server dependencies with evaluations currently paused ([Source](https://docs.univer.ai/guides/pro)). FortuneSheet preserves a useful filter schema under MIT, yet its lineage carries a GPL contamination incident and small-team maintenance risk. That combination of constraints preserves your renderer and formula-engine investment while avoiding lock-in, copyleft exposure, and full-editor weight. For a team that needs only sort, filter, and selection rather than editing, the evidence points to a thin overlay-plus-index layer with header hit-boxes, HTML dropdowns, a hidden-row index separate from manual hide, and stable multi-key sort specified from Excel and Sheets behavior.

## Quadratic sets the canvas performance ceiling you should study, not ship

Quadratic is the closest public reference for a 60fps canvas grid with pinch-zoom, built as a **WebGL canvas spreadsheet on PixiJS with custom MSDF shaders, spatial-hash viewport virtualization, and a three-thread pipeline** ([Source](https://www.quadratichq.com/blog/building-a-high-performance-spreadsheet-renderer-why-we-chose-webgl-over-html)). The team rejected per-cell DOM because **10,000 visible cells means 10,000+ DOM elements** with uncontrollable reflow and draw-call explosion ([Source](https://www.quadratichq.com/blog/building-a-high-performance-spreadsheet-renderer-why-we-chose-webgl-over-html)). Text stays crisp from 0.01x to 10x by storing distance-to-glyph-edge in a **single 42px MSDF atlas for OpenSans plus Noto Sans fallback** ([Source](https://www.quadratichq.com/blog/building-a-high-performance-spreadsheet-renderer-why-we-chose-webgl-over-html)). Four shader types split backgrounds, grid lines, MSDF text, and sprites, with **tinted versus non-tinted text shaders saving about 33% vertex buffer** in the common black-text case ([Source](https://www.quadratichq.com/blog/building-a-high-performance-spreadsheet-renderer-why-we-chose-webgl-over-html)). The headline claim to design against is **100,000 visible cells in 10–50 draw calls per frame** ([Source](https://www.quadratichq.com/blog/building-a-high-performance-spreadsheet-renderer-why-we-chose-webgl-over-html)).

Virtualization is hash-based viewport culling plus LRU eviction, not row-window DOM recycling. Each **15-column by 30-row spatial hash owns its vertex buffers so an edit recalculates only that hash**, an order-of-magnitude reduction over full-viewport rebuilds, with progressive loading with padding and eviction when memory exceeds 500MB ([Source](https://www.quadratichq.com/blog/building-a-high-performance-spreadsheet-renderer-why-we-chose-webgl-over-html)). Computation is split across a **Rust-to-WASM core worker holding data and operations, a TypeScript render worker doing text layout and vertex buffers, and the main thread running PixiJS input and GPU render**, with the core tracking a viewport copy via SharedArrayBuffer and shipping only changed cells as zero-copy transferable buffers ([Source](https://www.quadratichq.com/blog/building-a-high-performance-spreadsheet-renderer-why-we-chose-webgl-over-html)). Local data and computation run on the machine by default ([Source](https://www.quadratichq.com/technology)), while Python ships as local Pyodide WASM and SQL, AI, multiplayer, connections, and scheduled tasks require server and cloud ([Source](https://docs.quadratichq.com/)). For officeview the borrowable ideas are hash buckets with per-bucket buffers, viewport-plus-padding fetch, a SharedArrayBuffer viewport mirror, and HTML overlays for header dropdowns positioned over canvas rather than canvas-drawn widgets. What not to borrow is the payload and ops footprint, since **self-host demands Docker, a license key, and a minimum of 4 cores with 12GB RAM across ten open ports** ([Source](https://github.com/quadratichq/quadratic-selfhost)).

On sort and filter Quadratic reached Excel parity only in mid-2026, which makes it a fresh specification rather than a mature dependency. **AutoFilter on plain ranges without converting to a table shipped in v0.26.13 in August 2026 with Ctrl+Shift+L, single-cell expansion to the surrounding data region, value checklists plus number and date conditions, SUBTOTAL awareness, and round-trip through Excel xlsx** ([Source](https://www.quadratichq.com/changelog)). The model worth copying is that **filtered rows hide the whole sheet row through a channel separate from manual Hide/Unhide, so unhide does not resurrect filtered rows, and sort reorders only visible body rows** ([Source](https://www.quadratichq.com/changelog)). Filter state is first-class and persisted, surviving Clear and row or column delete, restoring on undo, shifting on insert or delete, and sitting under a top-level Data menu with Filter, Clear, and Reapply ([Source](https://www.quadratichq.com/changelog)). Formula-level **SORT and FILTER operate as new-view array functions**, distinct from view-state autofilter ([Source](https://www.quadratichq.com/formulas/sort)).

## Univer and FortuneSheet give you state models worth copying and stacks worth skipping

Univer Sheets renders on **Canvas2D via a shared engine-render scene-graph of Engine, Scene, and Object, not a DOM grid** ([Source](https://docs.univer.ai/guides/recipes/architecture/rendering)). The architecture guide describes the engine as inspired by Konva, Fabric, and Babylon and built to unify docs, sheets, and slides ([Source](https://docs.univer.ai/guides/recipes/architecture/rendering)). Critically for a viewer, **cell text typesetting in sheets completely reuses the docs stack so cells support all document typesetting capabilities** ([Source](https://docs.univer.ai/guides/recipes/architecture/rendering)). Scenes compose a main Spreadsheet object plus row-header, column-header, and corner-rect objects ([Source](https://docs.univer.ai/guides/recipes/architecture/rendering)), and **components support canvas-as-buffer caching with incremental viewport drawing during scroll** ([Source](https://docs.univer.ai/guides/recipes/architecture/rendering)). A custom SheetExtension point allows worksheet-scoped drawing beneath native text that survives resize, hide, freeze, scroll, and zoom ([Source](https://docs.univer.ai/showcase/sheets/custom-canvas)). The pattern to lift is separation of Engine from Scene from ViewObjects plus a single text-layout path shared between renderer and editor to avoid metric drift.

The plugin system is a microkernel where **core holds only essential logic and engine-render, ui, and sheet are all plugins** ([Source](https://docs.univer.ai/blog/this-is-univer)). Composition is explicit, loading only needed plugins such as core plus engine-render plus sheets plus sheets-ui plus sheets-sort and sheets-filter ([Source](https://docs.univer.ai/guides/recipes/architecture/univer)). All mutations flow through commands, with **cancellable before and after event pairs such as SheetBeforeRangeSort with SheetRangeSorted and SheetBeforeRangeFilter with SheetRangeFiltered** ([Source](https://docs.univer.ai/guides/docs/features/core/general-api)). Sort ships as **model plus UI packages with worksheet single-column sort and range multi-key sort** ([Source](https://docs.univer.ai/guides/sheets/features/sort)). Filter ships as **filtering model, commands, and services plus a separate UI package with get, create, remove, per-column criteria, and filtered-out row indexes** ([Source](https://docs.univer.ai/guides/sheets/features/filter)). The exact model to copy is an AutoFilter object holding a range plus a map from column to criteria where each column holds either a value list or up to two custom conditions with an AND flag, with filtering computing a hidden-row set via getFilteredOutRows rather than reordering, while sorting mutates order through a range-sort command. Mutations such as SetSheetsFilterRangeMutation, SetSheetsFilterCriteriaMutation, RemoveSheetsFilterMutation, and ReCalcSheetsFilterMutation run through a filter service ([Source](https://github.com/dream-num/univer/blob/dev/packages/sheets-filter/src/commands/mutations/sheets-filter.mutation.ts)). A viewer can implement the same split of non-destructive hide versus destructive reorder and drive it through OT-friendly mutations so undo and collaboration keep working.

FortuneSheet is the only Luckysheet line worth evaluating in 2026, and only as a pattern source. **Luckysheet stopped maintenance with an October 2021 notice that the core team was building Univer** ([Source](https://github.com/dream-num/Luckysheet/issues/799)) and a January 2024 notice that it had completed its mission ([Source](https://github.com/dream-num/Luckysheet/issues/1454)), with its last npm release as 2.1.13 in January 2021 ([Source](https://www.npmjs.com/package/luckysheet)). The correct fork is **ruilisi/fortune-sheet with about 3.6k stars and releases alive through v1.0.4 in November 2025** ([Source](https://github.com/ruilisi/fortune-sheet/releases)). It documents **filters supporting color, numerical, date, and text filtering plus simultaneous multi-field sort** ([Source](https://ruilisi.github.io/fortune-sheet-docs/guide/)). Its inherited state model defines a filter_select range plus per-column filter entries with caljs conditions, a computed rowhidden map, and range bounds, where caljs takes priority over picked rows ([Source](https://ruilisi.github.io/fortune-sheet-docs/guide/sheet.html)). The full caljs vocabulary covers about twenty types across empty, text, date, numeric, and between semantics ([Source](https://ruilisi.github.io/fortune-sheet-docs/guide/sheet.html)). That schema maps cleanly onto read-only viewing by applying rowhidden without editing. The rendering lesson is narrower, since the grid viewport draws on canvas while menus, toolbar, formula bar, and dialogs are HTML template strings ([Source](https://cloud.mo4tech.com/excel-luckysheet-source-code-analysis.html)), coordinates map to cells by binary search over visible-pixel arrays, and every refresh calls a full visible-area redraw that contemporary review flags as unoptimized. Borrow the coordinate mapping, viewport-only draw, and filter-to-hidden model without copying full-redraw-per-change or the global Store singleton.

Alternative grids clarify the canvas-versus-DOM fork. **Glide Data Grid is MIT-licensed single-canvas with lazy on-demand cell rendering and native scrolling proven past 100 million rows** ([Source](https://github.com/glideapps/glide-data-grid)), which is why its header hit-testing, lazy providers, and overlay dropdown techniques deserve a spike even though it offers no Excel-like filter UI. Handsontable, AG Grid Enterprise, and RevoGrid are the best specifications for that UI, with **Handsontable enabling row virtualization by default unless renderAllRows is set** ([Source](https://handsontable.com/docs/javascript-data-grid/row-virtualization/)) and **RevoGrid keeping the original source intact while virtualization renders only the viewport and large local filters run in short batches** ([Source](https://rv-grid.com/guide/filters)). Handsontable enables filtering with filters plus dropdownMenu and per-type condition tables plus programmatic addCondition and filter ([Source](https://handsontable.com/docs/14.3/javascript-data-grid/column-filter/)), while RevoGrid exposes system, multi-column, conditional, slider, header, and custom filters with blank-semantics and cell-parser normalization plus beforefilterapply interception for remote filtering ([Source](https://rv-grid.com/guide/filters)). Adopting any of them whole abandons the existing canvas renderer, so their value is as interaction specs and API shapes rather than embeds.

## Each reusable option hides one dealbreaker that rules out wholesale adoption

Quadratic tempts as a high-performance reference but **as of March 2026 Quadratic is now closed-source** ([Source](https://www.quadratichq.com/blog/comparing-the-5-best-open-source-spreadsheets)), with the main quadratichq/quadratic repository gone from the organization listing that retains only self-host, docs, and small libraries ([Source](https://github.mosekj.com/quadratichq)). That single fact converts every Quadratic idea into clean-room work, because snapshot mirrors carry unconfirmed redistribution rights and the supported path is commercial self-host or SaaS. FortuneSheet tempts as MIT-licensed continuity but merged **HyperFormula under GPLv3 in January 2025 then reverted it in v1.0.1 and deprecated the tainted releases** ([Source](https://github.com/ruilisi/fortune-sheet/pull/655)), against a background where HyperFormula removed its free non-commercial license and gated versions behind keys ([Source](https://hyperformula.handsontable.com/docs/guide/licensing.html)). The caution is therefore to pin at or above v1.0.4, audit transitive dependencies, and never reintroduce HyperFormula without GPLv3 compliance or a commercial license. Univer tempts as permissive modern architecture but **import and export are server-provided through an Exchange worker plus Temporal plus object storage** ([Source](https://docs.univer.ai/guides/pro/import-export)), Pro extends OSS with collaboration, import/export, and printing under a commercial license with watermark and quota limits without a key ([Source](https://docs.univer.ai/guides/pro)), and **new Pro purchases and 30-day evaluations are temporarily paused during an AI-harness pivot** ([Source](https://pro.univer.ai/)). The caution is to depend only on OSS model packages and keep conversion pluggable rather than gating a viewer MVP on Pro evaluation. Glide tempts as the proven canvas scaler but it is **React-only and a data-grid rather than a workbook**, so borrowing means header and overlay techniques rather than spreadsheet fidelity. Handsontable and AG Grid Enterprise tempt as the most Excel-faithful filter UIs but their production fidelity is **per-developer commercial licensing with Enterprise tiers and volume negotiation**, plus a forced migration from canvas to DOM virtualization that discards the host renderer advantage. JSpreadsheet Community tempts as MIT free but **virtual rendering past 100k rows is Pro-only while Community grinds to a halt past a few thousand rows** ([Source](https://bossanova.uk/jspreadsheet/blog/jspreadsheet-ce-vs-pro)), with most Community commits from one maintainer, so Community health does not transfer. x-spreadsheet tempts as a tiny canvas embed at **about 199.8KB JS plus 23.3KB CSS** ([Source](https://registry.npmjs.org/x-data-spreadsheet-dt4)) but maintenance is explicitly described as slowed ([Source](https://web.reogrid.net/articles/reogrid-vs-luckysheet-x-spreadsheet)) with a minimal autofilter toggle rather than a condition engine, so it saves no real work. ONLYOFFICE tempts as full fidelity but Community is **AGPL-3.0 with commercial Enterprise from $1,500 and Developer from $3,500 depending on connections and term** ([Source](https://www.onlyoffice.com/compare-editions)), which makes tens of megabytes plus server plus license review disproportionate for viewing-only sort and filter. EtherCalc and SocialCalc tempt as zero-license-cost collaboration but carry mixed copyleft and legacy licenses plus self-host ops with no large-data virtualization story, so their apparent cheapness is the most misleading of all.

## Excel-faithful viewing needs a checklist, two conditions, and honest state

Excel opens filtering through Data then Filter with **each header gaining a drop-down arrow that opens filter choices with number or text filters depending on column type** ([Source](https://support.microsoft.com/en-us/excel/quick-start-filter-data-by-using-an-autofilter)). The value section is **a list box with every entry in the column each carrying its own checkbox topped by Select All** ([Source](https://www.dummies.com/article/technology/software/microsoft-products/excel/how-to-use-autofilter-in-excel-2019-259697/)), with **a search box above the list for typing text or numbers to narrow choices** ([Source](https://support.microsoft.com/en-us/excel/quick-start-filter-data-by-using-an-autofilter)). Type-specific entries open submenus where **pointing to Number or Text Filters shows a menu of conditions, choosing one opens criteria entry, and And requires both while Or requires either** ([Source](https://support.microsoft.com/en-us/excel/quick-start-filter-data-by-using-an-autofilter)). Color filtering opens **font-color swatches, fill-color swatches, and cell-icon choices sourced from manual or conditional formatting** ([Source](https://www.dummies.com/article/technology/software/microsoft-products/excel/how-to-use-autofilter-in-excel-2019-259697/)). The same menu carries **Sort A to Z and Sort Z to A alongside filter-by-color and filter-by-number-or-text accelerators** ([Source](https://support.microsoft.com/en-US/Accessibility/excel/use-a-screen-reader-to-sort-or-filter-a-table-in-excel)), with **per-column Clear Filter plus Data-tab Clear for all criteria** ([Source](https://support.microsoft.com/en-us/office/filter-data-in-a-range-or-table-01832226-31b5-4568-8806-38c37dcc180e)). Date columns deserve special handling because **the checkbox list groups dates hierarchically by year, month, and day with expandable nodes** ([Source](https://www.thebricks.com/resources/guide-how-to-filter-by-date-in-excel-using-ai)), and **a Blanks checkbox appears only when the column actually contains blanks** ([Source](https://support.microsoft.com/en-us/office/filter-data-in-a-range-or-table-01832226-31b5-4568-8806-38c37dcc180e)). Sheets differs structurally with **Sort A to Z, Sort Z to A, Sort by color, Filter by condition with an optional custom formula, Filter by values with uncheck-to-hide, search, and Filter by color closed by OK** ([Source](https://support.google.com/docs/answer/3540681?hl=en)), plus **right-click Filter by cell value that bypasses the popup** ([Source](https://support.google.com/docs/answer/3540681?hl=en)).

Operators funnel into a compact Custom AutoFilter dialog that a viewer can implement once and reuse everywhere. Text offers **Equals, Does Not Equal, Begins With, Ends With, Contains, Does Not Contain, plus Custom Filter** ([Source](https://www.dummies.com/article/technology/software/microsoft-products/excel/how-to-use-autofilter-in-excel-2019-259697/)), numbers offer **Equals through Less Than Or Equal To plus Between, Top 10, Above Average, Below Average, and Custom Filter** ([Source](https://www.pk-anexcelexpert.com/data-sort-and-filter/chapter-4/)), and dates offer **fixed Equals, Before, After, and Between plus dynamic presets from Today and Yesterday through This, Next, and Last Week, Month, Quarter, and Year plus Year to Date and All Dates in the Period** ([Source](https://www.pk-anexcelexpert.com/data-sort-and-filter/chapter-4/)). Dynamic presets **evaluate against the computer date each time the filter is applied or reapplied so a saved This Month filter stays current** ([Source](https://www.pk-anexcelexpert.com/data-sort-and-filter/chapter-4/)), while **All Dates in the Period compares the same month or quarter across every year** ([Source](https://www.pk-anexcelexpert.com/data-sort-and-filter/chapter-4/)). The dialog itself shows **Show rows where with an operator dropdown plus value box, And/Or buttons, and a second operator plus value row for up to two combined criteria** ([Source](https://www.trainingconnection.com/excel/lessons/filtering-lists.php)), with **wildcard support for question mark, asterisk, and tilde escapes** ([Source](https://support.microsoft.com/en-us/office/filter-data-in-a-range-or-table-01832226-31b5-4568-8806-38c37dcc180e)). Top 10 needs exactly **a Top or Bottom selector, a number spinner defaulting to 10, and an Items or Percent selector** ([Source](https://www.excelfunctions.net/excel-autofilter.html)) and is **only available for columns Excel identifies as numeric** ([Source](https://www.excelfunctions.net/excel-autofilter.html)). Sheets backend breadth is wider, spanning **NUMBER_GREATER through NUMBER_NOT_BETWEEN, TEXT_CONTAINS through TEXT_EQ plus email, URL, DATE_EQ through DATE_NOT_BETWEEN, ONE_OF_LIST, BLANK, CUSTOM_FORMULA, and related enums** ([Source](https://github.com/googleapis/google-api-php-client-services/blob/main/src/Sheets/BooleanCondition.php)), so a viewer that supports the Excel core plus Between, Not Between, Is Empty, Is Not Empty, and one custom-formula escape hatch covers the Sheets intersection without overbuilding. Two Excel constraints simplify implementation, since **a column accepts a value list or a criterion but not both, and icon versus custom filter are mutually exclusive** ([Source](https://support.microsoft.com/en-us/office/filter-data-in-a-range-or-table-01832226-31b5-4568-8806-38c37dcc180e)), and **mixed-type columns show only the condition submenu for the majority type** ([Source](https://support.microsoft.com/en-us/office/filter-data-in-a-range-or-table-01832226-31b5-4568-8806-38c37dcc180e)).

Multi-level sort belongs in a dialog rather than the dropdown, because quick sorts are single-key while the dialog supports **up to 64 ordered levels** ([Source](https://support.microsoft.com/en-us/excel/sort-data-in-a-range-or-table-in-excel)). Each level is a Column by Sort On by Order triple where **Sort On selects Cell Values for text, number, or date versus Cell Color, Font Color, or Cell Icon for format** ([Source](https://support.microsoft.com/en-us/excel/sort-data-in-a-range-or-table-in-excel)). Order vocabulary is type-specific with **A to Z or Z to A for text, Smallest to Largest or Largest to Smallest for numbers, Oldest to Newest or Newest to Oldest for dates, plus Custom List** ([Source](https://support.microsoft.com/en-us/excel/sort-data-in-a-range-or-table-in-excel)). Levels support **Add Level, Copy Level, Delete Level with at least one entry retained, and Up or Down reordering where higher entries sort first** ([Source](https://support.microsoft.com/en-us/excel/sort-data-in-a-range-or-table-in-excel)). The dialog must persist **My data has headers so headers stay put** ([Source](https://trumpexcel.com/multiple-level-sorting-excel/)), offer **case-sensitive matching through Sort Options** ([Source](https://support.microsoft.com/en-us/excel/sort-data-in-a-range-or-table-in-excel)), and require explicit ordering for color sorts since **there is no default cell, font, or icon sort order and the user must define it as On Top or On Bottom** ([Source](https://support.microsoft.com/en-us/excel/sort-data-in-a-range-or-table-in-excel)). Guardrails matter as much as fields, since **sorting a single column raises a Sort Warning offering Expand the selection versus Continue with the current selection** ([Source](https://trumpexcel.com/multiple-level-sorting-excel/)). Sheets confirms the simpler end of the spectrum with **Data then Sort range then Advanced range sorting options plus Data has header row plus Add another sort column** ([Source](https://support.google.com/docs/answer/3540681?hl=en)) and an API model where **a filter holds multiple sort specifications applied in order** ([Source](https://developers.google.com/workspace/sheets/api/guides/filters)).

State communication and keyboard behavior determine whether the viewer feels trustworthy. Excel signals through glyphs where **a drop-down arrow means filtering is enabled but not applied with a Showing All tooltip, while a funnel means a filter is applied with a tooltip naming the criterion** ([Source](https://support.microsoft.com/en-us/office/filter-data-in-a-range-or-table-01832226-31b5-4568-8806-38c37dcc180e)). Filtering **hides entire rows that fail any column criterion** ([Source](https://support.microsoft.com/en-US/Excel/use-autofilter-to-filter-your-data)) and **additional column filters are additive on the current subset** ([Source](https://support.microsoft.com/en-us/office/filter-data-in-a-range-or-table-01832226-31b5-4568-8806-38c37dcc180e)), except that **Top 10 and Above or Below Average evaluate against the original range rather than the already-filtered subset** ([Source](https://support.microsoft.com/en-us/excel/get-started/filter-data-in-a-range-or-table-in-excel)). Other columns then offer **only values visible in the currently filtered range** ([Source](https://support.microsoft.com/en-us/office/filter-data-in-a-range-or-table-01832226-31b5-4568-8806-38c37dcc180e)), the value window shows **only the first 10,000 unique entries** ([Source](https://support.microsoft.com/en-us/office/filter-data-in-a-range-or-table-01832226-31b5-4568-8806-38c37dcc180e)), and **only one filter range applies per sheet at a time** ([Source](https://support.microsoft.com/en-us/office/filter-data-in-a-range-or-table-01832226-31b5-4568-8806-38c37dcc180e)). Filters do not auto-refresh, so the viewer must offer explicit Reapply when **data is added, modified, deleted, or recalculated** ([Source](https://support.microsoft.com/en-us/office/filter-data-in-a-range-or-table-01832226-31b5-4568-8806-38c37dcc180e)). Sheets adds the status readout Excel lacks, showing **at the bottom right the number of rows displayed out of total rows** ([Source](https://support.google.com/docs/answer/3540681?hl=en)), with **filter settings saved even if filtered data is removed** ([Source](https://support.google.com/docs/answer/3540681?hl=en)). Keyboard parity starts from **Ctrl+Shift+L to toggle AutoFilter, Alt+Down to open the dropdown, Alt+A S A or S D for quick sorts, Alt+A S S for the Sort dialog, and Ctrl+Alt+L to reapply after data changes** ([Source](https://support.microsoft.com/en-US/Accessibility/excel/use-a-screen-reader-to-sort-or-filter-a-table-in-excel)), with **Space toggling checkboxes and Tab reaching OK inside the menu** ([Source](https://support.microsoft.com/en-US/Accessibility/excel/use-a-screen-reader-to-sort-or-filter-a-table-in-excel)). For assistive technology the norms to implement are **menu and menubar containers with menuitemcheckbox roles, roving tabindex, and aria-checked or aria-disabled** ([Source](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/)) plus **a multi-select listbox with type-ahead, aria-selected, aria-setsize for virtualized value lists, and separate Select All controls** ([Source](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/)).

## Conclusion

Build a viewing-only interaction layer directly on the owned canvas renderer using Univer-style command mutations and a Quadratic-style separate filter-hidden channel, specify the dropdown, condition set, 64-level sort dialog, and glyph-plus-count state from Excel and Sheets, and borrow canvas hit-testing and batched-filtering tactics from Glide and RevoGrid without embedding any whole grid or editor. That combination delivers Excel-plausible sort, filter, and selection in weeks rather than quarters while keeping licensing clean under Apache-2.0 and MIT pattern reuse, deferring Univer Pro import, export, collaboration, and print until genuine editing or server fidelity demands them, and leaving Quadratic, Handsontable Enterprise, AG Grid Enterprise, and ONLYOFFICE as paid references rather than dependencies.

# Web Spreadsheet/Data-Grid Alternatives for Canvas Sort/Filter Viewing

## Which options render on canvas and virtualize well past 100k rows?

### Takeaway
Only Glide Data Grid and x-spreadsheet (and by comparison ReoGrid Web, not in scope) are single-canvas renderers; AG Grid, Handsontable, RevoGrid and JSpreadsheet are virtualized-DOM grids, while ONLYOFFICE and o-spreadsheet are full spreadsheet editors (canvas + DOM overlays) and EtherCalc/SocialCalc are legacy DOM with no large-data virtualization.

### Cited Findings
- Glide Data Grid is “A canvas-based data grid, supporting millions of rows, rapid updating, and native scrolling” — “It scales to millions of rows. Cells are rendered lazily on demand” — “Scrolling is extremely fast. Native scrolling keeps everything buttery smooth” — “Why does Data Grid use HTML Canvas? Originally we had implemented our Grid using virtualized rendering [react-virtualized] … Once you need to load/unload hundreds of DOM elements per frame nothing can save you” — [Source](https://github.com/glideapps/glide-data-grid)
- Glide Data Grid “can handle scrolling 100 million rows without dropping frames” and “100-1,000x more than most other grids … run a fully-playable version of Doom” — [Source](https://www.glideapps.com/blog/glide-data-grid-typescript)
- Glide Data Grid is MIT licensed, ~5,296 stars, 127 open issues, React 16–19, maintained by Glide — [Source](https://github.com/glideapps/glide-data-grid)
- Handsontable “Render only visible cells for blazing-fast performance with large datasets. This grid has 1 million cells” and “Row virtualization … process hundreds of thousands of records without causing the browser to hang … draws only the visible part of the grid” enabled by default unless `renderAllRows:true`; column virtualization likewise enabled by default — [Source](https://handsontable.com/docs/javascript-data-grid/row-virtualization/) ; [Source](https://handsontable.com/docs/javascript-data-grid/performance/) ; [Source](https://handsontable.com/features)
- Handsontable scrolling performance “depends mainly on … Number of cells … Amount and complexity of custom renderers … Number of options enabled” — [Source](https://handsontable.com/docs/javascript-data-grid/row-virtualization/)
- RevoGrid “Virtual rendering is the default … renders visible rows and columns + small buffer + pinned regions”; `frameSize` controls off-screen buffer; `disableVirtualX/Y` opt out; “Render 1M+ rows and millions of cells with no hard row limit … Virtualization keeps the DOM focused on the visible viewport” with “Intelligent Virtual DOM: Smart row recombination” — [Source](https://rv-grid.com/guide/performance) ; [Source](https://www.npmjs.com/package/@revolist/revogrid)
- RevoGrid “filtering … keeps the original `source` intact … lets row virtualization render only the small portion currently in the viewport … Large local filter operations automatically run in short batches so the browser can stay responsive” — [Source](https://rv-grid.com/guide/filters)
- RevoGrid best practice: “Treat virtualization as the default … renders only the visible rows and columns plus a small frame” — [Source](https://rv-grid.com/guide/patterns)
- x-spreadsheet is canvas-rendered, “very small package … draws to a single canvas, so scrolling is smooth and the footprint is minimal” vs Luckysheet DOM “Large” bundle — comparison table: ReoGrid Web Canvas / Luckysheet DOM / x-spreadsheet Canvas — [Source](https://web.reogrid.net/articles/reogrid-vs-luckysheet-x-spreadsheet)
- x-spreadsheet: 14,594–14,605 stars, 1,752 forks, 412 open issues, MIT, tags `canvas, es6, excel` — [Source](https://github.com/myliang/x-spreadsheet/)
- x-spreadsheet dist: `xspreadsheet.js (199.8KB)`, `xspreadsheet.css (23.3KB)` plus locales — [Source](https://registry.npmjs.org/x-data-spreadsheet-dt4)
- JSpreadsheet CE vs Pro: “Virtual rendering (100K+ rows)” = No in CE, Yes in Pro (Enterprise/Ultimate); “If dataset goes over a few thousand rows … go Pro! When you don't have virtual rendering, it can grind to a halt” — [Source](https://bossanova.uk/jspreadsheet/blog/jspreadsheet-ce-vs-pro)
- o-spreadsheet: “A standalone spreadsheet for the web … All basic features … Real time collaboration … Import/Export of excel file format”, 292 stars, 83 forks, 5,213 commits on `20.0` branch, live demo — [Source](https://github.com/odoo/o-spreadsheet)
- EtherCalc is “a web spreadsheet for real-time collaborative editing … TypeScript rewrite on Cloudflare fullstack (Hono + Workers + Durable Objects + D1 + KV + R2) … self-hosts anywhere via docker compose”, 3.1k stars, 552 forks, 1,783 commits, browsers Safari/Chrome/Firefox; no virtualization claim; legacy Redis path pinned to `0.20201228.1` — [Source](https://github.com/audreyt/ethercalc)
- AG Grid filtering overview lists Column / Quick / External / Advanced filters as distinct enterprise-capable types — [Source](https://www.ag-grid.com/javascript-data-grid/filtering-overview/)

### Inferences
- Canvas + past-100k: Glide Data Grid is the only in-scope option proven past 100k–1M+ rows on canvas with native scroll; x-spreadsheet is canvas but tiny/basic with no large-data story and light maintenance, so its virtualization should not be trusted past tens of thousands of rows without own work.
- DOM-virtualized past-100k: AG Grid Enterprise, Handsontable, RevoGrid core, and JSpreadsheet Pro all claim 100k–1M+ via viewport virtualization, but they pay DOM churn cost (custom renderers, many enabled plugins degrade scroll) — relevant because the host renderer is already canvas, so adopting them whole means abandoning canvas.
- o-spreadsheet (Odoo) is almost certainly canvas + DOM overlay like ONLYOFFICE (Odoo docs describe canvas grid), but this was not confirmed via fetch — treat as inference.
- ONLYOFFICE Spreadsheet Editor is a full-fidelity editor (canvas grid + DOM chrome) designed for workbook fidelity, not for embedding as a 100k-row virtualized viewer; its weight dominates any virtualization benefit.
- EtherCalc/SocialCalc have no credible 100k-row virtualization story; EtherCalc’s 2026 rewrite is about deployment (Workers/Durable Objects) not grid virtualization.

### Gaps
- No reliable source fetched on exact Glide bundle KB, AG Grid Community vs Enterprise row-model limits, o-spreadsheet rendering internals (canvas vs DOM), ONLYOFFICE grid rendering internals, or measured fps/row-count benchmarks past 100k for any option.
- JSpreadsheet Pro virtualization internals (row-window size, buffer) not found.

## Which offer Excel-faithful auto-filter UIs out of the box vs DIY APIs?

### Takeaway
Handsontable, AG Grid Enterprise, JSpreadsheet Pro, and ONLYOFFICE/o-spreadsheet offer Excel-like auto-filter UIs out of the box; RevoGrid offers a strong DIY filter framework (system + custom + Pro slider/date/cascade); Glide Data Grid and x-spreadsheet require DIY header-menu + predicate work.

### Cited Findings
- Handsontable: “Use the dropdown menu in column headers to filter data by conditions or values” and “Click column headers to sort. Supports multi-column sorting with Cmd/Ctrl+click” — [Source](https://handsontable.com/features)
- Handsontable: “Filter data by values or by a set of conditions, using Handsontable's intuitive user interface or flexible API” — “built-in filtering interface resembles Excel's” — “if you want to implement your own interface, you can easily filter data programmatically, using Handsontable's API”; enable via `filters:true` + `dropdownMenu:true`; per-type condition tables; `filters.addCondition()` + `filters.filter()` for quick/external filter; sort via `columnSorting` / `multiColumnSorting` with `initialConfig`, custom `compareFunctionFactory` — [Source](https://handsontable.com/docs/14.3/javascript-data-grid/column-filter/) ; [Source](https://handsontable.com/docs/javascript-data-grid/api/options/)
- Handsontable formulas: “Use spreadsheet formulas powered by HyperFormula. Supports 400+ functions including SUM, AVERAGE, IF” — [Source](https://handsontable.com/features)
- AG Grid filters: Column Filter, Quick Filter (across all columns), External Filter (app-owned), Advanced Filter (multi-column visual builder with type-ahead) — [Source](https://www.ag-grid.com/javascript-data-grid/filtering-overview/)
- AG Grid Enterprise adds “Advanced filtering (set, multi filters)”, row grouping/tree, aggregation, pivot, master/detail, server-side row model — [Source](https://www.simple-table.com/blog/ag-grid-pricing-license-breakdown-2026)
- RevoGrid filtering: “Predefined system filters. Multi column filters. Conditional filters. Preserve existing collections. Selection. Slider. Header filtering. Custom filters”; blank semantics configurable (`blankSemantics`, `isBlank`), `cellParser` normalization, `customFilters`, `beforefilterapply` / `beforefiltertrimmed` interception for remote filtering; Pro adds “Advanced Selection Filtering … Cascade … Slider … Header Input … Date Filter … Grouping Aggregation” — [Source](https://www.npmjs.com/package/@revolist/revogrid) ; [Source](https://rv-grid.com/guide/filters) ; [Source](https://rv-grid.com/guide/api/revoGrid)
- RevoGrid sorting: “Multiple options, customizable per column, with advanced event handling” via `sorting` prop + `updateColumnSorting(prop, order, additive)` + `beforesorting/aftersortingapply` events — [Source](https://rv-grid.com/guide/api/revoGrid) ; [Source](https://github.com/revolist/revogrid/blob/main/readme.md)
- JSpreadsheet: sorting and filtering = Yes in CE, Pro Enterprise, Pro Ultimate; “Editable cells … Sorting and filtering … Toolbar … Context menus” shared; differences are formulas/xlsx/virtualization/collaboration — [Source](https://bossanova.uk/jspreadsheet/blog/jspreadsheet-ce-vs-pro)
- JSpreadsheet formulas: “two tiers: Formula Basic, included by default, and Formula Pro, available as extension … Matrix … %/@ operators … Range A:A/1:1 … Extended Formulas … Private Scope … Formula Picker”; homepage claims “500+ compatible formulas” — [Source](https://jspreadsheet.com/docs/formulas) ; [Source](https://jspreadsheet.com/)
- JSpreadsheet xlsx: “Import 16+ formats including .xlsx, .csv and .ods, preserving formatting and formulas” and “Import from XLSX / Export to XLSX” are Enterprise/Ultimate extensions (not CE); “Excel import … Multiple worksheets … formatting … Formulas … Charts … Validations … Comments” — [Source](https://jspreadsheet.com/) ; [Source](https://jspreadsheet.com/pricing)
- x-spreadsheet toolbar includes `autofilter.js (160B)` component, `formula.js`, `freeze.js`, `merge.js` — i.e. minimal auto-filter toggle exists, not an Excel condition/value-checklist UI — [Source](https://registry.npmjs.org/x-data-spreadsheet-dt4)
- x-spreadsheet scope: “Formula support is basic, xlsx fidelity is limited, and many features (rich number formats, conditional formatting, robust merge/border round-trip) you'll end up building yourself” — [Source](https://web.reogrid.net/articles/reogrid-vs-luckysheet-x-spreadsheet)
- o-spreadsheet feature list implies full spreadsheet (filters/sort/formulas/collab/xlsx) but no filter-UI detail was fetched; live demo is the evaluation path — [Source](https://github.com/odoo/o-spreadsheet)
- ONLYOFFICE Docs includes Spreadsheet Editor in all editions (Community/Enterprise/Developer) with full Excel-style filter/sort/formula support by virtue of being a complete editor — [Source](https://www.onlyoffice.com/compare-editions)
- EtherCalc REST API surface preserved; docs at `docs.ethercalc.net`, API in `API.md`; no auto-filter UI claim found — [Source](https://github.com/audreyt/ethercalc)

### Inferences
- Most Excel-faithful out-of-box: ONLYOFFICE > Handsontable ≈ AG Grid Enterprise > o-spreadsheet ≈ JSpreadsheet Pro > RevoGrid (framework + Pro UI packs) > x-spreadsheet (toggle only) > Glide (DIY — data-grid, not spreadsheet; sorting/filtering via app predicates and custom header cells) > EtherCalc/SocialCalc (legacy, not Excel-faithful).
- For “viewing (not full editing)” the critical pattern to copy is: header dropdown → value checklist (with search) + condition rows per dtype (text/number/date) + multi-column AND + clear/apply + API `addCondition/filter/sort` equivalents; Handsontable and AG Grid docs are the best specifications for this.
- Glide’s value for this project is not its filter UI (it has none Excel-like) but its canvas interaction model: lazy cell providers, overlay editors, custom header rendering in canvas.
- o-spreadsheet likely has the closest canvas + filter-state model to the host project, but filter-condition depth needs direct demo/docs verification.

### Gaps
- No fetched source enumerating Glide’s built-in sort/filter UI (docs/storybook not fetched); no fetched source on o-spreadsheet filter conditions or ONLYOFFICE filter API; no fetched source on JSpreadsheet filter condition types.
- Formula support for Glide/RevoGrid/AG Grid (non-spreadsheet grids) assumed none/DIY; not explicitly sourced beyond Handsontable/JSpreadsheet/o-spreadsheet/ONLYOFFICE/x-spreadsheet-basic.

### Inferences
- Cheapest integration for canvas-viewing-only: copy patterns, not code — $0 license, small incremental canvas work (header hit-boxes, dropdown overlay, predicate + hidden-row index, sort comparator).
- Embedding whole: Glide (MIT, React-only, canvas) and RevoGrid Community (MIT, framework-agnostic web component) are cheapest to try; AG Grid Community (MIT) is free but forces DOM migration; full editors (ONLYOFFICE, o-spreadsheet, JSpreadsheet Pro, Handsontable) trade license fees ($1K–$13K+/yr) plus large bundle (grids ~hundreds KB–MBs; full editors tens of MB + server) and integration (theming, data-model, collab, AGPL/commercial review).
- JSpreadsheet’s per-app (vs per-dev) model can be cheaper for many devs/one app but certificate-expiry-as-code-change and obfuscated Pro source are integration risks.
- EtherCalc/SocialCalc $0 license is misleading: mixed copyleft/commercial-legacy licenses + self-host/ops + missing xlsx-fidelity/virtualization make integration effort high.

## Which projects are healthy vs dormant in 2026?

### Takeaway
Healthy in 2026: AG Grid, Handsontable, RevoGrid, JSpreadsheet Pro, o-spreadsheet, ONLYOFFICE, and EtherCalc-rewrite; slowed/dormant for embedding purposes: x-spreadsheet, JSpreadsheet CE, SocialCalc legacy.

### Inferences
- Worth (a) embedding whole — narrow cases only: Glide Data Grid if the host is React and team accepts a data-grid (not workbook) dependency for viewing; RevoGrid Community if a DOM grid is acceptable and Pro filter packs justify a commercial seat; o-spreadsheet if team wants a full MIT/LGPL-ish spreadsheet with collab/xlsx and Odoo-backed health (verify license + canvas fit first). Full editors (ONLYOFFICE, JSpreadsheet Pro/Handsontable/AG Grid Enterprise) are overkill for “sort/filter viewing” on an existing canvas renderer.
- Worth (b) learning interaction patterns from — highest ROI: AG Grid Enterprise (set/multi/advanced filter UX, server-side patterns), Handsontable (Excel-like condition tables per dtype + `addCondition/filter` API + multi-sort), RevoGrid (filter pipeline events `beforefilterapply/trimmed`, blank semantics, batched large-data filtering, `getVisibleSource`), o-spreadsheet (canvas spreadsheet model/filter state if confirmed), ONLYOFFICE (fidelity reference only). Glide is worth studying for canvas hit-testing, lazy providers, overlay dropdowns, and native-scroll performance.
- Worth (c) ignoring for this goal: x-spreadsheet (dormant, too minimal, would require rebuilding conditions/xlsx/virtualization); JSpreadsheet CE (no virtualization/formulas/xlsx, single-maintainer risk — Pro health does not transfer); SocialCalc/EtherCalc legacy (no virtualization, mixed legacy licenses, collab-server ops, not Excel-faithful); ONLYOFFICE as embed (AGPL trigger + server + tens-of-MB bundle for viewing-only is disproportionate — reference only).
- Ranked verdict for canvas sort/filter viewing: 1) DIY on existing canvas using AG Grid + Handsontable + RevoGrid specs (cheapest, preserves renderer); 2) spike Glide header/overlay techniques for canvas dropdowns; 3) evaluate o-spreadsheet filter model/demo as canvas-spreadsheet reference; 4) do not embed x-spreadsheet / EtherCalc / SocialCalc / JSpreadsheet CE; 5) pay for Handsontable/AG Grid Enterprise/RevoGrid Pro/JSpreadsheet Pro/ONLYOFFICE only if scope expands to full editing + xlsx fidelity + support/SLA.

- No commit-date/release-cadence verification for Glide, AG Grid, Handsontable, RevoGrid, o-spreadsheet, ONLYOFFICE in this pass; health inferred from live docs/pricing/version strings, not git log.

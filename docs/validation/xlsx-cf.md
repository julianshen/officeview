## 1. AppleScript Dictionary Probe vs. XML Authoring (Excel 16.114)

Probed via `sdef "/Applications/Microsoft Excel.app"` and live AppleScript execution against Excel for Mac `16.114`:

1. **Dictionary coverage**:
   - `class range` declares `element type="format condition"` (`code="X227"`), supporting `make new format condition at range ...` for basic `cell value` / `expression` conditions, plus `modify condition` (`code="smXLXMFc"`) and `modify applies to range` (`code="smXL2572"`).
   - Specialized rule classes (`above average format condition` `X322`, `top 10 format condition` `X321`, `unique values format condition` `X323`, `color scale format condition` `X325`, `databar format condition` `X312`, `icon set format condition` `X315`) expose read/write inspection properties (`format condition type`, `format condition priority`, `stop if true`, `applies to`, `number format`, `interior object`, `font object`, `above or below`, `number of standard deviations`, `top 10 rank`, `top 10 percentage`, `duplicate or unique`), and return `«constant **** S  »` when reading the `format condition type` enumerator of `uniqueValues` / `duplicateValues`.
2. **Why deterministic XML authoring + Excel open/resave/capture is used**:
   - AppleScript cannot author arbitrary `<extLst><ext uri="{78C0D931-6437-407d-A8EE-F0AA7539E650}"><x14:conditionalFormattings>` blocks, deliberately divergent vs. absent helper `<formula>` elements on `containsText` / `containsBlanks` / `containsErrors`, or explicit `<dxf>` clear attributes (`<b val="0"/>`, `<u val="none"/>`, `<strike val="0"/>`).
   - `scripts/cf-refs/generate.ts` therefore authors deterministic raw SpreadsheetML archives (`ZIP_DATE = 2026-01-01T00:00:00Z`, fixed row height `18 pt`, fixed column width `14 chars`, paired CF and unformatted control columns), and `scripts/cf-refs/build.ts` opens each archive in Excel 16.114 to verify repair-free loading and live `format conditions` object-model registration before resaving/capturing.
3. **Workbook close semantics (`closeOwnedWorkbook`)**:
   - When closing the last open workbook in Excel 16.114, `tell application "Microsoft Excel" to get name of every workbook` returns `"missing value"`. `closeOwnedWorkbook` in `scripts/cf-refs/build.ts` treats `workbookNames() === undefined` as closed and enforces `assertCanCloseWorkbook` so pre-existing open workbooks (such as `活頁簿1`) are never closed.

## 1. AppleScript Dictionary Probe vs. XML Authoring (Excel 16.114)

Probed via `sdef "/Applications/Microsoft Excel.app"` and live AppleScript execution against Excel for Mac `16.114`:

1. **Dictionary coverage**:
   - `class range` declares `element type="format condition"` (`code="X227"`), supporting `make new format condition at range ...` for basic `cell value` / `expression` conditions, plus `modify condition` (`code="smXLXMFc"`) and `modify applies to range` (`code="smXL2572"`).

2. **Why deterministic XML authoring + Excel open/resave/capture is used**:
   - AppleScript cannot author arbitrary `<extLst><ext uri="{78C0D931-6437-407d-A8EE-F0AA7539E650}"><x14:conditionalFormattings>` blocks, deliberately divergent vs. absent helper `<formula>` elements on `containsText` / `containsBlanks` / `containsErrors`, or explicit `<dxf>` clear attributes (`<b val="0"/>`, `<u val="none"/>`, `<strike val="0"/>`, `<patternFill patternType="none"/>`).
   - `scripts/cf-refs/generate.ts` therefore authors deterministic raw SpreadsheetML archives (`2026-01-01T00:00:00Z`, fixed row height `18 pt`, fixed column width `14 chars`, paired same-content unformatted control rows/columns), and `scripts/cf-refs/build.ts` opens each archive in Excel 16.114 to verify repair-free loading and live `format conditions` object-model registration before resaving/capturing.
3. **Workbook close semantics (`closeOwnedWorkbook`) & non-destructive single-case rebuild**:
   - When closing the last open workbook in Excel 16.114, `tell application "Microsoft Excel" to get name of every workbook` returns `"missing value"`. `closeOwnedWorkbook` in `scripts/cf-refs/build.ts` treats `workbookNames() === undefined` as closed and enforces `assertCanCloseWorkbook` so pre-existing open workbooks are never closed.
   - `generateAllStage1({ onlyCaseId })` in `scripts/cf-refs/generate.ts` mutates only the targeted case when `--case <id>` is used and preserves any existing Excel-resaved pending workbooks (`resavedByExcel === true` or `savedSha256 !== inputSha256`).
4. **Host Geometry Conversion & Display Format Inspection (Excel 16.114 macOS Quartz)**:
   - Live AppleScript inspection on Excel 16.114 confirms:
     - `string value of range "..."`: returns the rendered display text (e.g. `1.25`, `2.50`, or narrow-column overflow `##`).
     - `underline of font object of display format of range "..."`: returns the exact CF winning underline state (`underline style none`, `underline style single`, `underline style double`).
     - `strikethrough of font object of display format of range "..."`: returns `true` or `false`.
     - `tell range "${range}" of ws to get its width`: returns point width at 72 dpi (width 14 = 84.0 pt; width 3 = 18.0 pt; total A1:G10 = 522.0 pt), confirming Excel for Mac on 72 dpi uses 6 points per character unit (`width * 6`).

## 3. Atomic Fail-Closed Composition & Stage 1 `[measure]` Capability Table

### Atomic Fail-Closed Rule: Known `not-matched` vs. `unresolved` (`stop-tainted` / `property-tainted`)

Per Spec §§5.7 and 6.5 and the Stage 1 staging rule:
1. **Known `not-matched`**: A supported rule whose capability is `verified` and whose predicate evaluates to `false` on a cell is **known `not-matched`**. It writes zero properties and does not trigger `stopIfTrue`; lower-priority rules proceed normally.
2. **Unresolved / Refused (`CfOutcome = 'unresolved'`)**: A rule overlapping a cell that is refused at parse time, depends on an unmeasured/pending oracle capability (`isCapabilityVerified(capId) === false`), belongs to a later stage (`expression`, `colorScale`, `dataBar`, `iconSet` in Stage 1), or fails runtime budget/preparation is **never treated as known `not-matched`**:
   - **`stop-tainted` (`stopIfTrue = true` or unknown rule header)**: If an unresolved rule overlapping a cell has `stopIfTrue="1"` (or its rule header/scope overflowed before `stopIfTrue` was known), it **halts/suppresses all lower-priority rules on that cell**. Higher-priority resolved properties written *before* the unresolved rule remain valid, while any lower-priority rule (such as a lower-priority red-fill rule under an unresolved higher-priority `stopIfTrue` rule) is withheld so it cannot paint a potentially wrong winner.
   - **`property-tainted` (`stopIfTrue = false`)**: If an unresolved rule overlapping a cell has `stopIfTrue="0"`, its `writes: CfWriteMask` (the exact set of DXF properties/visual slots it writes, or `ALL` when its DXF or rule type is unknown) **taints** those properties on that cell. No lower-priority rule may write any property in the tainted set; affected properties are withheld (`unresolved`) rather than letting a shadowed lower-priority rule win.

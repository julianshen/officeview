# Stage 5 performance and memory audit (Task 43)

Base: `416e5426`, `feature/pivots-s5`. Inspection was read-only before fixes; regressions live in `tests/xlsx-pivots-stage5-audit.test.ts`. Counts are deterministic model/element counts, not a physical heap or quiet-machine certification.

## Findings and fixes

1. **Medium — quadratic hidden-item comparison** (`InteractiveSheetDoc.tsx`, slicer apply / `sameSlicerHiddenItems`). Clearing a previously filtered 10,000-item control compared expected and actual hidden indices using repeated `includes`: **50,005,000 source element reads**. Reachable in the mounted resident and paged adapter. Extracted the unchanged comparison first, reproduced RED, then replaced lookup with one Set: **10,000 reads**, O(n) time and O(n) admitted workspace. This is not a 50-million-record source scan: it is a menu-index comparison.
2. **Medium — pre-admission item copies** (`slicers/controller.ts`, enqueue). A denied 10,000-item selection still mapped 10,000 selectable ids and built sets. RED records 10,000 id reads despite refusal; GREEN records **0**. Admission now precedes vector/set construction and covers a conservative **256 + 128*visibleItems + 128*allItems** bytes (2,560,256 B at 10,000/10,000), retained until replacement/disposal. Labels are shared, not copied. Bounds are model bytes, not measured native heap. Invalid identities/refused apply release the hold.
3. **Medium — worker composite construction before checking its grant** (`viewerSession.ts`, combinePivotOverlays/controlApply). A small per-sheet grant was reserved, but copied vectors and the OwnedRects index could exceed it before the post-build check. The helper now sums lengths and checks the model cost before touching elements; 10,000 rectangles under a 512 B grant refuse with **0 element reads**, and controlApply rolls back all target/composite/reply charges. Existing unlimited/default callers retain their prior admission responsibility.
4. **Medium, latent API defect — early construction refund** (`slicers/transaction.ts`, dropStage). Cancel/close released 100 B while an ignoring producer remained pending. The generic helper has **no production instantiation** (worker uses its own staging); do not attribute this to the mounted worker path. Now 100 B remains through cancel/close/abort and is refunded once after the late candidate is discarded. Admission can consequently refuse newer requests until older producers drain.
5. **Medium, latent API defect — incomplete commit** (`slicers/transaction.ts`, commit). `every([])` accepted an in-flight target set. It now returns stale while building and leaves the still-charged stage available to finish. A later explicit commit succeeds only after staging completes.

## Bounds and paths inspected

- Four-target synthetic transaction: 20 alternating cancel/commit+close cycles, **80 target constructions**, peak **400 B**, every cycle ends at **0 B**. All 400 B is reserved before the first construction. This measures the staging primitive, not four real mounted pivots.
- Existing `SharedControlIndexCache` regression: **100,000 visits / one build**, eight shared leases, **1,500,000 model bytes**, last release -> 0. This is a helper test; the helper is not instantiated by the viewer, and is not evidence that real linked pivot computations share a scan.
- Worker `controlApply`: bounded target loop; per-target candidate grants plus shared reply and per-sheet composite grants; preflight all revisions/linkage, synchronous all-target commit, cancel rolls back. Each actual target can recompute its own pivot (O(targets * records)); **no claim of a single shared computation across real pivots**. Targets are capped by MAX_LINKED_CONTROL_TARGETS. UI currently refuses any multi-target control, not only different-layout ones.
- Slicer action maps/sets are linear in <=10,000 identities. Slicer painter/layer enumerates visible rows/columns rather than rendering 10,000 DOM buttons. No records scan per displayed item was found.
- Timeline: a 100-year daily source produces fewer than 100 periods in a 600px box; allocation follows visible width, not the 36,525-day range. Period calculations use UTC. Drag/scroll remain refused under S5-C.
- Controller register/filter-indicator indexing can revisit other controls of the same field (control-count dependent); it does not scan pivot records. This small-control metadata path is not certified at unbounded control counts.
- Slicer/timeline overlap: the adapter refuses an overlapping unsupported filter instead of guessing conjunction/order. Worker linkage, grants, stale revisions and rollback are covered by the existing worker suites; mounted resident/paged tests cover supported selection and clear.
- Control-free sheets retain conditional lazy control mounting; no new tile work or eager import was added by these fixes.

## Limits

Task 43's full interaction browser matrix and owner recipes are **not complete**. The current browser spec is saved-paint/collapse smoke, not proof of all Stage 5 gestures, focus restoration or CLS. S5-C deliberately leaves R1/R3/R4/R5/R6/R7 refused/unverified. Table-slicer filtering and four-pivot UI updates were not enabled to manufacture passing coverage. Cross-sheet paged target discovery and reset of all live control state still need the orchestrator's whole-feature review. These are disclosed coverage/feature limitations, not accepted Excel measurements.

Its final slide contains an image blip with no relationship; PowerPoint also reports it cannot display the image. Keep this source error distinguished from renderer defects; do not manufacture image content.

Confirmed renderer defects:

* Empty `a:ln` creates an invented black outline even without an inherited line definition. Native text boxes/overlays have none.
* Picture `a:alphaModFix amt=25000/30000` is ignored, causing bright backgrounds. Table-cell solid-fill alpha is lost, turning source-transparent cells white.
* Text font names occur in `a:latin/a:ea/a:cs` children, not the run-property `typeface` attribute. The deck embeds four compressed EOT font parts, currently unread: Microsoft YaHei regular/bold, MiSans regular and Liter regular. A temporary prototype using `mtx-decompressor` 1.8.0 successfully decodes all four and Node Canvas registers them. Liter measures the 54pt bold title second line at ~487px within its 530px source box; the fallback currently wraps it incorrectly.
* Paragraphs are laid out as one independent line flow per run; adjoining colored/bold runs split, previous-run bold leaks into following runs, leading whitespace is trimmed, explicit breaks create extra empty lines, wrapping ignores `bodyPr@wrap`, and source paragraph spacing is omitted.

Correct the source-driven behavior, then compare all 21 slides in Dia using the public pipeline. No fixture-specific names, sizes or coordinates in production code. Pixel parity is not required across different font rasterizers; expected titles, inline-run flow, code indentation, transparent tables, opacity and object order are required. Preserve explicit false/zero; support child font faces, font size, bold, italic, solid/theme color and character spacing. Preserve end-paragraph formatting for an empty paragraph/break without forcing its size on existing nonempty text. Lay out one paragraph as styled spans sharing lines. Preserve source whitespace and explicit breaks, with a single line advance per break and no unconditional trimming. Honor body wrap none, insets, paragraph margins/indent, tabs/default stops, percent/point line spacing and before/after spacing, alignment and vertical block anchor. Wrapped continuation lines keep paragraph indent and bullets only at paragraph start. Long unbreakable text must make progress; use grapheme-safe segmentation where breaking is permitted, without separating combining clusters or emoji. Preserve script runs for browser shaping. Use a measurable line/run representation and an injectable fixed-measure seam for deterministic coordinate/line tests. Avoid tests depending on installed fonts.

Native-backed spacing contract: normal single-line advance is 1.2 times the largest content font size in pixels. Percentage line spacing multiplies that normal advance; explicit point spacing remains an exact baseline advance converted at 96/72. This is a line-leading rule, not a change to font size or measured glyph widths. The initial raw-font-point-only interpretation produced visibly compressed text and is superseded by this independently controlled evidence. Keep measured baseline/ink placement coherent and document remaining font-engine differences.

Paint segments at their placed positions with the same fonts/settings used for measurement, preserve caller state/outer affine placement, and record searchable logical text in source order. Character spacing must affect both placement and recorded widths; when the browser supports letterSpacing use it, with a tested consistent fallback for headless Canvas. Do not globally rescale unrelated text metrics to fit this fixture. Add phrase-search/selection tests across adjoining styles and explicit lines using actual painting. Preserve existing logical reading order and legacy handwritten PptxTextBody models.

Implementation contract: an optional recording-hook symbol carries a distinct paragraph source identity/text per painting invocation and UTF-16 source offsets for placed segments.
